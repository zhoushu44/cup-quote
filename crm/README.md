# 客户营销系统（本地独立版）

从印刷 ERP 同步客户档案和历史订单，按每个客户自己的下单周期判断「该复购了没」，生成每日跟进名单，按业务员分组复制后发微信；业务员跟进后在系统里点结果，客户进入冷却期，到期再提醒。

**目前是独立于报价系统的本地版本，确认好用之后再并入。** 对 ERP 只读，不回写任何数据。

## 启动

双击 `启动.bat`，浏览器打开 <http://127.0.0.1:6656>。没有 Node.js 时脚本会自动用 DeepSeek Harness 自带的 Node。

## 账号

第一次打开会让你**创建主管账号**（就是你自己，密码至少 6 位）。之后在「设置 → 人员」里给业务员建账号：

| 角色 | 能做什么 |
|---|---|
| 主管 | 看全部客户、改规则、管账号、同步 ERP、看所有人的跟进记录 |
| 业务员 | 只看自己名下的客户，跟进、写备注；没有设置页，不能同步 ERP |

业务员账号要选 ERP 里的业务员名字，和客户档案里的「业务员」对上才会看到自己的客户。忘了密码由主管在人员表里「改密码」。

密码只存加盐哈希（`data/users.json`），登录状态 30 天，同一个账号 10 分钟内错 5 次会暂停登录。

## 数据从哪来

| 本地文件 | 来源 | 内容 |
|---|---|---|
| `data/customers.json` | ERP 客户档案 `/base/visitors/list` | 名称、联系人、手机、微信、业务员、等级、地址 |
| `data/orders.json` | ERP 销售订单 `/order/saleorder/list` | 单号、产品、数量、金额、下单时间、作废标记、流转状态 |
| `data/settings.json` | 本系统 | 规则参数 |
| `data/notes.json` | 本系统 | 每个客户的备注、「不做营销」标记 |
| `data/follows.json` | 本系统 | 每个客户的跟进记录 |
| `data/users.json` | 本系统 | 账号（密码只存加盐哈希） |
| `data/erp.json` | 本系统 | ERP 账号 |

整个 `data/` 目录都在 `.gitignore` 里，不会进仓库。

同步方式：主管点右上角「同步 ERP」，或设置页「立即同步」。数据超过 12 小时，下次打开页面会自动同步一次。全量约 1 分钟。

## 页面

### 概览
客户总数、重点客户数、待跟进 / 今日已跟进 / 沉睡数量，以及每个业务员的分布。点业务员名字直接进他的今日跟进名单。

### 今日跟进
今天要跟的客户，按优先级排（重点客户在前，逾期越久越靠前）：

| 状态 | 判断方法 |
|---|---|
| 已逾期 N 天 | 距上次下单的天数已经超过这个客户的复购周期 |
| N 天后到期 | 已过周期的 80% |
| 沉睡（仅重点客户） | 重点客户里超过周期 3 倍、且 90 天以上没下单的 |

筛好业务员后点「复制名单（发给业务员）」，生成一段文字，直接粘到微信。没选业务员时会按业务员分段，一次复制所有人。

### 跟进之后
两种记法，效果一样，这个客户都会从名单里消失一段时间（冷却期）：

- **在名单上直接记**：每一行「跟进 / 备注」一格里有个「＋ 记录跟进…」下拉，选一个结果就记好了，客户原来的备注保留不动。要写情况就选最下面的「写备注 / 看详情…」。
- **点开客户记**：先写情况，再点一个结果按钮，写的情况同时成为这个客户的备注。

| 结果 | 多久后再出现在名单里 |
|---|---|
| 有意向，等回复 | 7 天 |
| 最近不需要 / 已经下单 / 联系不上 | 30 天 |

- 天数可以在设置页改。
- **冷却期间客户下了单**：周期自动重算，不用等。
- 再次出现时带着「上次跟进：谁、什么时候、什么结果、备注」，复制到微信的文字里也带。
- 名单上勾「只看已跟进的」能看到冷却中的客户。

### 跟进记录
谁在什么时候跟了哪个客户、结果是什么、写了什么。按业务员、按时间段看，底部按人统计条数。

### 跟进统计
不只看今天。选一个周期（今天 / 近 7 天 / 近 30 天 / 本月）和业务员：

- **六个数**：跟进次数、覆盖客户、等回复、已下单、最近不需要、联系不上
- **业务员排行**：按客户归属，条形是跟进次数，后面是各种结果的个数和覆盖了多少个客户
- **趋势**：今天看按小时，其余按天；下面有日均和最多的一天
- **跟进明细**：这段时间每一笔，点一行打开客户

排行里「等回复」「已下单」才是真出活的，光看次数会被「最近不需要」刷高。

### 沉睡唤醒
所有沉睡客户，人比较多（目前约 2700 个），从上往下联系，或按业务员分下去。

### 全部客户
所有客户，可以搜名字、联系人、手机、备注。点一行打开详情：当前状态、复购周期、常买产品、历史订单明细（作废的单划掉）、跟进。

**不做营销**：同行、内部账号（例如「现货」）、已关门的客户勾上，就从所有名单里消失。

## 规则（设置页可改，改完立即重算）

**重点客户**，满足任意一条：
- 近 12 个月采购金额 ≥ 5 万元
- 近 12 个月单数 ≥ 10 单，且金额 ≥ 2 万元（挡掉单多但量很小的）

**复购周期** = 这个客户相邻两次下单间隔（7~365 天之间）的中位数。

**沉睡** = 超过周期 3 倍且 ≥ 90 天没下单；只下过一单的客户 90 天没动静也算沉睡。
**流失** = 超过 365 天没下单，不再进跟进名单，只在「全部客户」里能看到。

## 需要确认的两点

1. **作废标记**：ERP 字典写的是 0 正常 / -1 作废 / 2 暂停 / 3 强制终止，但实际数据里没有 -1，作废单记的是 **1**；而标记为 3 的单大量出现在已完工的订单上。目前只把 1 当作不算数。建议跟 ERP 那边核实 3 的含义，如果 3 也该排除，在设置页勾上即可。
2. **重点客户的门槛**是按数据分布定的（目前标出 121 个），多了或少了直接在设置页调数字。

## 注意

- 现在有登录了，但走的还是普通 HTTP。**只在本机或公司内网用，不要直接把端口开到公网**；要外网访问先加 HTTPS。
- ERP 密码是明文存在 `data/erp.json` 里的。
- 页面截图在 `docs/` 里，只留在本机，不进 git（里面有真实客户信息）。

## 自测

```bash
node tools/smoke.js      # 接口：登录与权限、筛选、跟进与冷却期、人员管理、规则、备注
node tools/ui-check.js   # 用无头 Chrome 把页面点一遍（建账号、登录、跟进、业务员视角），截图到 docs/
```

两个测试都会复制一份数据到临时目录、起一个独立的服务来跑（`tools/env.js`），测完删掉，不会动真实数据，也不会在真实数据里留下测试账号。排查时可用 `CRM_TEST_PORT` 固定端口、`CRM_TEST_TRACE=1` 打印服务端连接日志。

`tools/distribution.js` 打印周期、金额的分布，用来调规则参数。
